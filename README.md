# 多时区应用日志小时桶重算

        面向一线复核人员的单服务数据工作台。样例数据随仓库提供，结论保留行号、原因码和原值。

        ## 业务模块

        - M1 日志采信：`/api/logs/import`（整段解析，旧入口）、`/api/logs/intake`（按来源登记文件代次、分段上传）
- M2 时间解析：`/api/time/normalize`
- M3 事件去重：`/api/events/dedupe`
- M4 小时分桶：`/api/buckets/rebuild`
- M5 迟到修订：`/api/watermark/advance`
- M6 批次对账：`/api/export/buckets.csv`

        ## 核心规则

        事件先归一到 UTC，DST 重叠时保留 fold；小时桶右端开，水位只能前进且迟到事件仍进入修订。

        ## M1 分段采信规则

        日志轮转按来源登记文件代次，分段上传而不是整文件覆盖：

        - 分片末尾不含换行的半截行保留为待补尾行（`pending_tail`），不当坏数据；与后续分片拼接补齐，物理行号在本代次内连续。
        - 换代（rotate）后新代次立即进入「接收中」，旧代次转「待补齐」；旧代尾行补齐后归入原批次（`batch_id`），两代证据不拼接、不伪造事件。
        - 明确结尾（end）冲刷最后一条尾行并置「完成」，完成代次拒绝再写入；结尾动作本身幂等。
        - 已接收位置按字节偏移登记；上传带 `expected_offset` 时，落后或错位的推进返回 422（`POSITION_CONFLICT`），并发换代的过期版本返回 `STALE_VERSION`。
        - 重试以 `(来源, 代次, 分片序号, 校验值)` 幂等：同序号同内容回放不重复入桶，同序号异内容返回 `SEGMENT_CONFLICT`。
        - 状态持久化在 SQLite，写入按单事务提交；进程中断后凭已接收偏移与待补尾行续传，不漏行、不重复。
        - 小时桶仅沿用 M4 既有取桶约定展示，不新增时区修正；去重仍由 M3 负责，本模块不新增请求去重规则。

        ## 启动

        ```bash
        docker compose up --build
        ```

        浏览器访问 `http://localhost:18212`。运行测试：

        ```bash
        docker compose exec -T app pytest -q
        ```

        ## 样例流程

        依次运行六个模块；最后在批次页复核输入、有效、隔离与输出合计。同一输入摘要重复执行时复用原 `run_id`。

        ## 已知不覆盖

        不处理加密文件与需要外部密钥的对象；不连接真实生产存储。
